Как работает поиск по документам

Семантический поиск: близость по смыслу, а не по словам

Карта пространства
косинусная близость 1.0 → 0.0 ближние (top-k) дальние

Запрос → вектор

"Сколько дней отпуска в году?"

текст -> токены -> вектор

сколькоднейотпускавгоду

поисковый вектор (dim 1536):
[0.81, -0.12, 0.47, 0.05, -0.33, 0.19, ...]

Запрос превращается в поисковый вектор той же размерности, что и фрагменты в индексе. каждый фрагмент уже хранится как вектор - сравнение идёт числами, а не словами.

Поиск по словам промахнулся бы здесь

В лучшем совпадении нет слова "отпуск" - только "ежегодный оплачиваемый отдых". Keyword-поиск его бы пропустил; семантический находит по близости векторов.

kNN — ранжирование по косинусу k = 3

  1. #1ежегодный оплачиваемый отдых - 28 дней0.92
  2. #2дни отдыха можно перенести0.86
  3. #3отгулы за переработку0.74
граница top-k
  1. #4командировочные расходы0.21
  2. #5оплата проезда0.19
  3. #6пропуск на вход в офис0.14

Модель видит только top-k ближайших фрагментов, а не весь архив.

Как читать карту. Документы заранее разбиты на фрагменты и сохранены в индексе как векторы (dim 1536). Запрос превращается в вектор; kNN / поиск ближайших соседей (часто приближённый, ANN) возвращает несколько лучших по косинусной близости. Плоскость - это 2D-проекция высокоразмерного пространства: реальная близость считается в 1536 измерениях. Кликните точку, чтобы заглянуть внутрь (семантический зум) и увидеть данные фрагмента.
